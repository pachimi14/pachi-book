# revise-episode：直す（オーナーの指摘・点検の結果・自分の気づき）

本文を直すときの手順。一行の直しも、場面の書き直しも、A／B の二択の案も、ここを通す。
初稿をどれだけ点検しても、オーナーの指摘で直す往復は残る。その往復で出す案が、チャットで考えたまま素通りしないようにする（2026-10-01 オーナー）。

2026-10-01 に起きたこと：二択で出した案の文を、オーナーが選んだあとで点検したら、前の話と順番が食い違っていた（EP020 の冒頭のツグミ）。
オーナーからは、案が点検済みか、チャットで考えたままかの区別がつかない。選ばれた案は「オーナー承認済み」として、あとの点検で引っかかっても通されかねない。

## 決まり
1. **オーナーに見せる文の案には、必ず点検の番号（P…）を付ける。** `propose.py` を通した案だけが番号を持つ。番号のない文を案として出さない。どうしても点検前に方向だけ相談したいときは「たたき（未点検）」と書いて出し、文は選ばせない。
2. **オーナーの「選ぶ」は、判断の承認であって、文の点検の免除ではない。** 選ばれた案や、オーナーが承認した文が、あとの点検（check_all・check_reader）で引っかかったら、「承認済みの P… で〇〇が引っかかった」とオーナーに報告し、直すかどうかを聞く。黙って通さない。黙って直さない。
3. **入れるのは、点検した文そのもの。** 選ばれた案は `propose.py --apply` で新しい版に入れる。手で打ち直して、点検した文とずらさない。
4. **オーナーが自分で書いてきた文は、そのまま入れる。** 書き換えない。入れたあとで `propose.py` にかけ、引っかかった所があれば一行で報告する（入れるのは止めない）。

## 手順
### 1. 何を直すかを決める
- 作品の fix-line の手順（`.claude/skills/fix-line/SKILL.md`）の 1〜3：オーナーの言葉で動きを決める／何がおかしいかを一行で言い直す／前後と台帳とあとの話のメモを読み直す。
- 直しが筋に触れる（場面を削る・足す、引きを変える、誰が何を知るかが変わる）ときは、先に章のあらすじ（`chapters/`）を直すか、オーナーに聞く。

### 2. 案を作り、自分で読む
- 案は、おすすめ一つか、二つまで。新しい数字・設定・現場の細部を足さない（反応の数字は除く）。
- 案の台詞を話している人物になって読む（fix-line の 4b）。前後の話と、出来事の順番（いつ・どこで・誰が見たか）を一行で言えるか。言えなければ出さない。

### 3. 点検にかける（必須）
案ごとにファイルを作る（直し所が何か所あってもよい）。

```
@@old
元の文（本文から一字一句そのまま）
@@new
直した文
```

```
python ../pachi-book/scripts/propose.py EPxxx Vn --issue "オーナーの指摘（一行）" --cand 案A.txt --cand 案B.txt
```

- 筋の点検（check_logic と同じ問い）と機械の点検（check_episode。直したことで新しく出た警告だけ）を回し、案に番号を付けて `notes/proposals.md` に記録する。
- 「直す」と出たら理由を読む。当たっていれば案を直して、かけ直す（新しい番号になる）。当たっていなければ、その理由を添えて出してよい。
- 新しい警告（AIっぽい型・読点の刻み・数字など）は、直してからかけ直す。
- 案が二つ以上のときは「好みの判定（参考）」も出る（`taste.py`：オーナーが選んだ・直した組を例に渡した判定役。測定で当たり75〜79%）。おすすめを選ぶ参考にする。判定で案を落とさない。
- オーナーの好みに近い案を作るために、案は言い回しの違いではなく、角度の違い（何を一番に気にしているか、どこで笑わせるか、削るか言い換えるか）で2〜4個出してよい。選ばれた記録がそのまま判定役の材料になる。

### 4. オーナーに出す
```
何を決めるか（一行）
- 案A（P…-A。筋：通る／機械：新しい警告なし／好み：1勝）：「案の文」
- 案B（P…-B。筋：直す〈理由：…。当たっていない理由：…〉）：「案の文」
おすすめ：A。理由（一、二行）。根拠の強さ（確かめたこと／推測）。
```
- 小さく、直し方がはっきりしている直し（誤字、オーナーの指摘そのものが直し方）は、二択にせず点検して入れ、番号と一緒に報告する。

### 5. 入れる
```
python ../pachi-book/scripts/propose.py EPxxx Vn --apply P…-A --to V(n+1)
```
- `--apply` は、選ばれた案と選ばれなかった案を好みの材料（`<taste_dir>/choices.jsonl`）に記録する。
- オーナーが案を選ばず自分で書いてきたときは、その文を入れたうえで `propose.py EPxxx Vn --owner-wrote 書いた文.txt --batch P<日時>` を回し、オーナーの文を選んだ側として記録する（一番よい材料）。
- 一つの版に複数の直しを入れるときは、入れた版を次の基準にして、次の案を点検し直す（前の直しで前後が変わっているため）。
- 入れたら `check_episode.py V(n+1) --base Vn` の字数を見る。

### 6. 採用の前
- 直しが数か所の小さなもの：`propose.py` の点検で足りる。
- 場面単位の書き直し、または直しが5か所を超えたとき：`check_all.py` と `check_reader.py` をかけ直す。オーナー承認済みの文が引っかかったら、決まり2のとおり報告する。

### 7. 記録
- コミットの件名に `(owner:X)`、`blocks/BAD-EXAMPLES.md` に元の文と直した文の組（fix-line の 7）。
- オーナーへの報告に、入れた案の番号を書く。番号から `notes/proposals.md` で点検の全文を引ける。
