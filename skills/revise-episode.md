# revise-episode：直す（付録。正本は docs/PROTOCOL.md §3-6・3-9）

オーナーの指摘・点検の報告・自分の気づきで本文を直すときの手の動かし方。経緯は docs/HISTORY.md。

## 決まり
1. 直すのはオーナーが選んだものだけ。点検の報告は提案で、書き手が自動で入れない。機械の ERROR・NG・再演・封印だけは例外（直して一覧で報告）。
2. オーナーに見せる文の案は「たたき（未点検）」か「案 A／B・推奨」。選ばれた案だけを `propose.py` にかけて番号（P…）を付け、`--apply` で入れる。手で打ち直さない。
3. 直しの基準はその話のメモと散文。案はメモの「本当に気にしていること」「誰が何を知る」「見せ場の台詞」を残す。残せない案は筋の変更なので、作らずにオーナーに聞く。
4. オーナーが自分で書いた文はそのまま入れる（notes/owner-lines.md に記録）。点検で引っかかったら直さず報告。
5. 本文で台詞や筋を変えたら、同じコミットで散文とメモに写す。
6. 整合のために説明を足さない。読者が常識で補えることは書かない。

## 手順
1. 何を直すかを一行で言い直す（事実／誰が何を知る／話し手／立場／指示語／人の動き／決定／声）。オーナーの言葉が直し方そのもののときは案を出し直さない。
2. その場面のメモの行を書き写し、本文の前後五行と台帳カードを読む。
3. 案は一つか二つ。角度の違いで出す（言い回しの違いで並べない）。新しい数字・設定・現場の細部を足さない。
4. オーナーが選んだら、案ごとのファイル（`@@old` / `@@new`）を作り：
   ```
   python ../pachi-book/scripts/propose.py EPxxx Vn --issue "指摘（一行）" --cand a.txt
   python ../pachi-book/scripts/propose.py EPxxx Vn --apply P…-A --to V(n+1)
   ```
   既定は機械の点検だけ。筋の差し込み点検が要るときだけ `--logic`。
5. 入れたら `check_episode.py V(n+1) --base Vn` で字数の増え方を見る。
6. コミットの件名に `(owner:A)` 作者の判断／`(owner:B)` 筋の整合ミス／`(owner:C)` 現場の知識／`(owner:D)` 文の欠陥／`(owner:E)` 直し案の外れ／`(owner:F)` 不足。
7. オーナーの指摘が次にも使える決まりなら blocks/RULES.md に一行、好みなら preferences.md に記録。禁止の一覧は作らない。
